# CPU-FIRST, WITH OPTIONAL GPU ACCELERATION.

# The CORE set below runs every stage of the pipeline (prepare / index /
# candidates / evaluate) on CPU, with no GPU and no model packages. The extras
# at the bottom are consumed only by the accelerator-beneficial stages
# (embedding generation, dense retrieval / FAISS, batched embedding similarity,
# transformer / cross-encoder re-ranking). Those stages resolve their device
# automatically via src/utils.resolve_device_from_config() and fall back to CPU
# when the packages are absent. Nothing below the CORE block is required to run
# the pipeline end to end.

# Lexical pair features (token/ratio similarity). C++ and parallelizes across
# cores; the review found no GPU edit-distance path worth using, so this stays a
# CPU dependency even on a GPU node.
#
# Uncommented because scripts/extract_pair_features.py (the matcher feature
# extractor) uses it for name_token_set_ratio / name_token_sort_ratio /
# name_partial_ratio. Those three degrade to NaN, with the condition recorded in
# the run's report, rather than the run failing - so the blocker and candidate
# stages still work without it, but the matcher's feature set does not.

# Gradient-boosted trees for the match classifier (scripts/train_model.py's

# so benchmark device=cuda before enabling it. scikit-learn provides GroupKFold.
scikit-learn>=1.3
lightgbm>=4.0
